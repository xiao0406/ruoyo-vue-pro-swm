# 信标管理 - 所属楼层下拉接口说明

**日期**：2026-04-08

---

## 概述

这份文档是写给前端同事看的。

“所属楼层”下拉不要再自己从全量建筑楼层树里筛了，改成走新的信标专用接口。  
新接口只返回**当前信标列表里实际用到的楼层**。

---

## 接口地址

**GET** ` /swm/swmBeaconStation/floorOptionsFromBeacon`

**请求参数**：无

---

## 返回规则

后端现在按下面这套规则返回下拉：

1. 先从 `swm_beacon_station` 里，按当前信标列表的口径，找出去重后的 `floorId`
2. 只查当前租户下的数据
3. 空值、空串不返回
4. 再用这些楼层 ID 去 `swm_site_map_management` 里翻译楼层名称
5. 只认 `mapType = 'floor'` 的节点
6. 如果翻译不到，就直接显示楼层 ID 本身

比如：

- 信标表里实际有 3 个楼层：`F001`、`F002`、`F999`
- 底图表里只找到：
  - `F001 -> 1层`
  - `F002 -> 2层`

那前端最终拿到的下拉就是：

- `F001 / 1层`
- `F002 / 2层`
- `F999 / F999`

---

## 返回示例

```json
{
  "success": true,
  "options": [
    {
      "value": "F001",
      "label": "1层",
      "floorName": "1层"
    },
    {
      "value": "F002",
      "label": "2层",
      "floorName": "2层"
    },
    {
      "value": "F999",
      "label": "F999",
      "floorName": "F999"
    }
  ],
  "total": 3,
  "message": "获取信标所属楼层选项成功"
}
```

---

## 前端怎么接

前端直接用：

- `value` 作为下拉选中值
- `label` 作为下拉显示文本

如果你们原来代码里更喜欢按字段语义取值，也可以继续用 `floorName`。

---

## 替换建议

如果前端现在是自己从建筑楼层树里再筛楼层，后面可以直接改成调这个接口：

**GET** ` /swm/swmBeaconStation/floorOptionsFromBeacon`

这样拿到的就是“当前信标实际用到的楼层”，不需要前端自己再做一轮过滤。

---

## 注意事项

- 这个接口是给“信标所属楼层下拉”专门准备的
- 它返回的是“信标实际用到的楼层”，不是系统里所有楼层
- 它只新增，不替换旧的建筑楼层树接口
- 旧接口保留不删，避免影响别的页面
