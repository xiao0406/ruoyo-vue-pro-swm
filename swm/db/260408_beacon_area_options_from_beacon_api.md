# 信标管理 - 所属区域下拉接口说明

**日期**：2026-04-08

---

## 概述

这份文档是写给前端同事看的。

“所属区域”下拉不要再直接拿全量区域表了，改成走新的信标专用接口。  
新接口只返回**当前信标列表里实际用到的区域**。

---

## 接口地址

**GET** ` /swm/swmBeaconStation/areaOptionsFromBeacon`

**请求参数**：无

---

## 返回规则

后端现在按下面这套规则返回下拉：

1. 先从 `swm_beacon_station` 里，按当前信标列表的口径，找出去重后的 `area`
2. 空值、空串不返回
3. 再用这些区域 ID 去 `swm_area` 里翻译区域名称
4. 如果翻译不到，就直接显示区域 ID 本身

比如：

- 信标表里实际有 3 个区域：`A100`、`A200`、`A999`
- 区域表里只找到：
  - `A100 -> 一车间焊接区`
  - `A200 -> 二车间装配区`

那前端最终拿到的下拉就是：

- `A100 / 一车间焊接区`
- `A200 / 二车间装配区`
- `A999 / A999`

---

## 返回示例

```json
{
  "success": true,
  "options": [
    {
      "value": "A100",
      "label": "一车间焊接区",
      "areaName": "一车间焊接区"
    },
    {
      "value": "A200",
      "label": "二车间装配区",
      "areaName": "二车间装配区"
    },
    {
      "value": "A999",
      "label": "A999",
      "areaName": "A999"
    }
  ],
  "total": 3,
  "message": "获取信标所属区域选项成功"
}
```

---

## 前端怎么接

前端直接用：

- `value` 作为下拉选中值
- `label` 作为下拉显示文本

如果你们原来代码里用的是 `areaName`，也可以继续用，后端这次保留了这个字段，方便平滑替换。

---

## 替换建议

原来如果调的是：

**GET** ` /swm/swmArea/getAreaOptions`

现在改成：

**GET** ` /swm/swmBeaconStation/areaOptionsFromBeacon`

返回结构基本兼容，不需要大改解析逻辑。

---

## 注意事项

- 这个接口是给“信标所属区域下拉”专门准备的
- 它返回的是“信标实际用到的区域”，不是系统里所有区域
- 旧接口保留不删，避免影响别的页面
